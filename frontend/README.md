# Playo Venue Observatory frontend

React/TypeScript dashboard backed by the existing Supabase historical dataset. The capstone root README and docs are authoritative for data and methodology.

Use Node 22+, install the committed pnpm lockfile, copy `.env.example` to `.env`, configure SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY, then run `pnpm dev`. Never commit actual environment files. Runtime bindings are read server-side by `lib/supabase-config.ts`.

Public routes: `/`, `/venues`, `/venues/:id`, `/sports`, `/cities`, `/analytics`, `/predictions`, `/data-quality`. `/data-management` and `/admin` require a verified Supabase account and protected admin membership. Older `/models`, `/quality` and `/workspace` routes remain supported.

`pnpm build` produces a Cloudflare-compatible Worker; `pnpm exec tsc --noEmit` validates TypeScript. Sites manages production runtime environment variables independently of local `.env`.

Admin membership can only be granted by a trusted database owner in `private.admin_members`. Sign-up never promotes a user. Historical data has no application write grants. Workspace operations require both admin membership and ownership, with audit events generated by a database trigger.

Supabase Auth access tokens are held in HttpOnly, SameSite=Strict cookies, Secure over HTTPS, capped at one hour. Refresh-token persistence is not implemented; sign in again after expiry. State-changing API requests require a matching Origin. No service-role key is used.
